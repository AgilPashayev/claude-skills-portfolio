What a skill is

A skill is a directory, not a chat snippet. The required file is SKILL.md: YAML frontmatter (name, description) plus the procedure. Extra markdown and scripts stay on disk until the instructions point at them.

Skill

Repeatable how-to. Loads when the description matches.

Rule / prompt

Short standing preference, or instructions for this thread only.

MCP

Tools and data connections. Complements skills; does not replace them.

Subagent

A separate agent for a delegated job, not a playbook on disk.

Progressive disclosure

  1. Startup. Only names and descriptions sit in context. You can keep many skills installed.
  2. Match. The user task hits trigger words in the description. The agent reads SKILL.md.
  3. Deepen. Linked files open if needed. Scripts are executed; their stdout returns, not the source. 
---
name: git-commit
description: Draft a conventional commit message from the current git diff.
  Use when the user asks to commit, write a commit message, or summarize staged changes.
---

Weak descriptions never fire. “Helps with git” is not a trigger. “Commit message from the current diff” is.

Install in an interview demo

cp -R skills/git-commit .cursor/skills/git-commit
# or
cp -R skills/git-commit ~/.claude/skills/git-commit

Then type /git-commit in Agent chat, or ask the agent to write a commit message. Cursor also loads .claude/skills/ for compatibility.

How I would talk through it

  • Start with cost: unused skills cost almost nothing because only metadata is hot.
  • Show pr-review as the disclosure pattern, then release-notes as the script pattern.
  • If they have an internal runbook, offer to turn one page of it into a skill on the whiteboard.
  • Name failure modes: vague descriptions, bloated files, secrets in markdown, Windows paths in shared skills.
