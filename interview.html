30-second pitch

Agent Skills are folders of instructions, optional reference files, and scripts. The model keeps only each skill's name and description in context, then reads SKILL.md when the task matches.

What this repo proves

  • git-commit — cheap skill, trigger-rich description.
  • pr-review — standards stay on disk until the review starts.
  • skill-audit — I lint skills like product surface.
  • release-notes — run a script; do not paste source into context.

Questions I expect

  • Skill vs prompt? Prompt is this chat. Skill is reusable and on-demand.
  • Vs MCP? MCP connects tools. Skills encode procedure.
  • Vs subagent? Subagent is another agent. Skill specializes this one.
  • Good description? Third person, what and when, words the user would actually say.
  • Team shipping? Keep skills in the repo, review them like code, never store secrets.

Five-minute demo

  1. Open the skills/ tree on GitHub.
  2. Show pr-review linking to STANDARDS.md.
  3. Show collect_commits.py as run-don't-paste.
  4. Copy one skill into .cursor/skills/ and invoke /git-commit.
